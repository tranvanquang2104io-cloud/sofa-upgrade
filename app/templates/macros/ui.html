Before these, every screen decided for itself how to render a page header, a status badge, an empty table or a set of filters, which is why the app read as three separately-built subsystems. These macros are the Bootstrap/Jinja equivalent of what SAP Fiori achieves with floorplans and Odoo with view inheritance: one canonical implementation per pattern, configured by data. Import at the top of a template — NOTE THE `with context`: {% from "macros/ui.html" import page_header, status_badge, ... with context %} `with context` is REQUIRED.     3. {% endif %} {% endfor %}
